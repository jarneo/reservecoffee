# 项目管理与配置需求整理（v1 草稿 · 待补充）

> 用途：在动手改代码前，先把需求结构化、明确术语，并标出需要拍板的点。
> 状态：草稿。用户确认 / 补充后，再进入实际小程序代码改造。
> 范围：微信小程序「二曜路8号咖啡和清酒」预约系统的**管理端与项目配置重构**。

## 0. 背景与目标

现有管理端：
- `pages/admin/projects`：仅能**新建**项目。
- `pages/admin/projectConfig`：项目配置（含"全部设定"、暂定/开放、每日次数上限、可提前天数等）。
- `pages/admin/sessions`：单日场次编辑。
- `pages/admin/view`：查看预约人。
- 底层：`projects` 集合含 `slotTemplate`（时段模板）、`openDays`（开放日）、`needReview`、`dailyLimit`、`advanceDays` 等字段。

目标：把"项目生命周期管理"（发布/下架/暂停/删除）收口到**项目管理页**；把"项目级规则配置"统一到**项目全局配置页**；合并场次设定；统一按钮逻辑；并补齐首次登录资料、提交校验等体验。特别地，原"项目配置 + 场次设置"两处将合并为**项目时间设置**（§2.1）统一日历编辑器，并在管理端新增**场次模版**页面（§3.1）。

## 1. 项目管理页面（`pages/admin/projects`）

| 能力 | 说明 |
|---|---|
| 新建项目 | 保留现有"新建"入口（右上角 / 底部按钮）。 |
| 删除项目 | **新增**。删除后该项目从管理列表与首页消失。建议为**软删除**（状态置 `deleted`，保留数据可恢复），而非物理删除。 |

| 状态展示 | 列表项展示当前状态徽标。 |
| 跳转 | 列表项点击 → 进入**项目全局配置页**。 |

**列表项卡片建议信息**：项目名 / 封面或图标 / 状态徽标（已发布·下架·开放预约·暂停预约）/ 行内操作（发布或下架、暂停或开放、删除）/ 点击其余区域进入配置。

## 2. 项目全局配置页面（`pages/admin/projectConfig`）

> 页面顶部为"项目时间设置"（见 2.1），其下依次为各配置区块。所有"周期性规则"类配置统一用**弹层 / 子页**呈现（见 2.3–2.5），交互一致。

### 2.1 项目时间设置（置顶 · 统一控制预约开放时间 + 场次）  ★本次重构核心
> 本区块替代原"项目配置 + 场次设置"两处，是项目级时间 / 场次的总控台，放在所有配置项最上方。

**用途**
1. 控制该项目的**预约开放时间**（哪些日期可约）；
2. 在对应的开放日期上**配置场次**。

**日历（复用现有日历逻辑并扩展）**
- 沿用现有日历组件与交互。
- **当前日期用橘色圆圈高亮**（视觉锚点，便于定位"今天"）。
- 开放日期在日历上以"已开放"标记呈现（圆点 / 高亮底），非开放日期弱化。
- 保留"批量开放 / 批量关闭"按钮；**移除"清除选择"**（见 §4）。

**选中日期 → 当日场次块向下排布**
- 点击某开放日期，下方以**每天一个块**的形式向下展开该日的场次（先设定本月开放预约日期，再逐日配置当天场次）。
- 每个"日期块"含：日期标题 + 当日场次列表 + 操作按钮（见下）。
- 非开放日期是否进入列表见待确认 Q11。

**单日场次编辑（日期块内）**
- 每场次：开始时间、结束时间（HH:MM 时间控件）、最大预约人数（默认 **8**）。
- 每个日期块有「**+ 添加场次**」按钮 → 弹层（§2.1.A）新增当天场次。
- 场次可删除 / 编辑。

**§2.1.A 弹层：添加 / 编辑场次**
- 字段：开始时间、结束时间、最大人数（默认 8）。
- "保存"写入当日场次；可选「采用模版」快捷填充（见 §3.1）。

**§2.1.B 弹层：选用模版（某天无场次时）**
- 当某天**没有场次数据**时，日期块内显示「选用模版」按钮 → 弹出层列出已保存的场次模版（§3.1）→ 选择后把该模版场次套用到当天。

**§2.1.C 弹层：复制场次**
- 每个日期块有「复制」按钮 → 弹出层提供三选项：
  1. **复制给指定某一天**：选择目标日期（日期选择器）→ 该日获得相同场次；
  2. **复制给本月所有**：本项目本月所有开放日获得相同场次；
  3. **复制给全局所有**：本项目全部开放日（跨月）获得相同场次（"全局"语义见 Q10）。
- 选择「指定某一天」后需再选一个日期；「本月所有 / 全局所有」逻辑一致，直接套用。

**与「可提前天数」的关系（已定，见 Q12）**
- **取消「可提前天数」**：§2.1 直接勾选的开放日期即为全部可约范围，用户在该开放日内任意可约，无需再叠加提前天数。原 §2.4 整节废弃（见 §2.4）。如需"最早可约天数"诉求，未来可加回为独立可选规则。

### 2.2 迁移并改名的原配置项
- 迁移原 projectConfig「全部设定」内容到本页。
- **"需审核" → 改名为"提交后是否审核"**（开关）。
- **移除"暂定 / 开放"按钮**（职责已移至项目管理页 1）。
- **"每日次数上限" → 改名为"预约次数限制"**，初值：**周期=每天，次数=2**。点击进入弹层配置（见 2.3）。

### 2.3 弹层：次数限定方式（预约次数限制）
形态与"预约开放规则""预约截止规则"保持一致（弹层或单独页面，周期性设置）。

- **设定周期**：每天 / 每周 / 每月 / 永久（分段选择器）。
- **周期内可提交次数**：数字输入，1,2,3,4,5,6……
- **管理员特权**：开关"管理员不受次数限制"。注：描述中"（可预约待定）"表示管理员预约行为细节待定（见 Q6）。

### 2.4 预约开放规则（**已废弃 · 见 Q12 已定**）
> **决策（Q12）**：取消「可提前天数」概念。§2.1 直接勾选的开放日期即为全部可约范围，无需再叠加提前天数。本节约等于废弃——"周期 + 提前天数 + 管理员特权"逻辑不再需要。
> 若日后确有"最早可约天数"诉求，再作为**独立可选规则**加回（不与开放日期强绑定）。

### 2.5 弹层：预约截止规则（新增）
- 新增的周期性规则，展现逻辑同 2.3：设定周期 + 截止条件（如"场次开始前 X 小时截止"或"当日 HH:MM 截止"，待确认，见 Q7）+ 管理员特权开关。

### 2.6 提交预约信息设置（新增）
- 针对**本项目**，配置预约人需填写的信息。
- 以**勾选**方式配置；默认勾选：**姓名、手机、微信号**三项。
- 可"新增可填写项"：备注、性别、年龄、同行人员等。
- 与第 6 节联动：姓名、手机为系统必填（不可取消），手机会做微信校验；微信号默认勾选但可选填（待确认，见 Q4）。

## 3.1 场次模版管理页面（新增 · admin 级，`pages/admin/slotTemplates`）

> 管理员在此维护**场次模版库**，供 §2.1.B「选用模版」与「添加场次」时快速套用。

- **入口**：管理端新增一级入口「场次模版」（与 项目管理 / 查看预约 / 管理员 并列）。
- **新增模版**：命名（如"周末双场""工作日晚场"）→ 配置场次列表（开始 / 结束 HH:MM、最大人数默认 8）→ 保存。
- **模版结构**：`{ _id, name, slots:[ {start,end,max} ], scope, createdAt }`。
- **适用范围（待确认 Q14）**：模版是**全 admin 共享**（跨项目复用）还是**按项目隔离**？建议全 admin 共享，便于多项目复用同一营业节奏。
- **复用**：在 §2.1.B 弹层中选模版 → 套用到指定日期；§2.1.A「采用模版」亦可快速填充。
- **管理**：模版可编辑 / 删除；删除不影响已套用到日期的场次（仅移除模版定义）。

## 7. 术语与状态定义（建议统一）

| 状态 / 术语 | 含义 | 首页可见？ | 接受新预约？ |
|---|---|---|---|
| 已发布（published） | 正常上线 | 是 | 取决于"开放预约" |
| 下架（offline） | 临时隐藏 | 否 | 否 |
| 开放预约（bookingOpen） | 接受新预约 | （随发布态） | 是 |
| 暂停预约（bookingPaused） | 暂停接单 | （随发布态） | 否 |
| 删除（deleted） | 软删除 | 否 | 否 |
| 开放日期（openDays） | 项目时间设置中勾选的可约日期（见 §2.1），与发布 / 预约态正交 | （随发布态） | 仅开放日可约 |

> 注："发布/下架"与"开放预约/暂停预约"是两个维度，可组合。例如：已发布 + 暂停预约 = 首页可见但不可约。

## 8. 待确认问题（Open Questions）

- **Q1 删除语义**：物理删除还是软删除？建议软删除（可恢复）。
- **Q2 下架 vs 删除**：下架后是否仍占管理列表？删除后是否彻底隐藏？（影响列表展示）
- **Q3 状态组合 UI**：五态如何在一行内清晰呈现？建议"发布态徽标 + 预约态徽标"双标签。
- **Q4 微信号必填性**：默认勾选但可选填，还是必填？姓名/手机为系统必填（不可取消）是否确认？
- **Q5 项目时间设置形态**：区间选择 / 星期开关 / 月份开关？与"预约开放规则"的提前天数如何分工？
- **Q6 管理员特权细节**："管理员不受次数限制"是否也豁免开放规则 / 截止规则？管理员能否代客预约（可预约待定）？
- **Q7 预约截止规则口径**：截止是"场次前 X 小时"还是"当日 HH:MM"或其他？周期如何作用？
- **Q8 用户资料存储**：昵称/头像存 `users` 集合，还是随预约记录？跳过后的默认值？
- **Q9 视觉风格（已定）**：**复刻已发布版视觉**——背景浅灰 `#F5F5F5`/白、文字 `#1A1A1A`、棕色 `#7A5230` **仅作点缀（logo 小圆点/品牌字），绝不做背景**。按钮黑底白字、ghost 白底黑边；chip 选中=加粗+黑边；徽标靠描边/字重区分不引入彩色；字体 `-apple-system, PingFang SC`。原型已按此重建为 v2（见 `project-config-prototype.html`）。
- **Q10 复制"全局所有"语义**：§2.1.C「复制给全局所有」指**本项目全部开放日（跨月）**，还是**所有项目**？建议本项目全周期。
- **Q11 非开放日期在日历列表中的呈现**：未开放的日期是否也出现在"向下日期块"列表中（置灰），还是完全不展示？建议仅展示已开放日期的场次块。
- **Q12 项目时间设置 vs 预约开放规则（advanceDays）分工**：§2.1 直接勾选开放日期；§2.4「可提前天数」在其上叠加"最早可约天数"。是否保留 advanceDays，还是改为"开放日期本身就是全部可约范围、无需提前天数"？需确认。
- **Q13 场次模版存储位置**：新增集合 `sessionTemplates`（推荐，admin 级共享）还是并入 `config_*` 文档？建议独立集合。
- **Q14 模版适用范围**：模版全 admin 共享（跨项目）还是按项目隔离？建议全 admin 共享。
- **Q15 当前日期橘色圈 vs 选中态视觉**：橘色圈（今天）与选中日期高亮需区分，避免混淆；建议今天用橘色细圈、选中用填充高亮。

## 9. 建议的数据模型变更（供后续实现参考，非最终）

`projects` 文档建议字段：

```
{
  _id, name, icon, image, intro,
  status: 'published' | 'offline' | 'deleted',     // 发布态
  booking: 'open' | 'paused',                       // 预约态（仅 published 时有效）
  needReview: bool,                                 // 提交后是否审核
  limit: { period: 'day'|'week'|'month'|'forever', count: 2, adminExempt: bool },  // 预约次数限制
  openRule: { period, advanceDays: 3, adminExempt: bool },                          // 预约开放规则
  deadlineRule: { period, ... , adminExempt: bool },                               // 预约截止规则
  fields: [ {key:'name',required:true}, {key:'phone',required:true}, {key:'wechat',required:false}, ... ], // 提交信息
  sessions: [ { date:'YYYY-MM-DD', slots:[ {start:'HH:MM', end:'HH:MM', max:8} ] } ], // 合并后的场次（在 §2.1 日历逐日编辑）
  openDays: [ 'YYYY-MM-DD', ... ],                  // 项目时间设置中勾选的可约日期（与 sessions 日期对应）
  timeRange: { ... },                               // 2.1 项目时间设置
  createdAt, updatedAt, ownerOpenid
}
```

> 注意：`slotTemplate` / `openDays` / `dailyLimit` / `advanceDays` 将被上述结构取代，需做数据迁移。

## 10. 预约项「图片介绍区域」（新增 · 2026-08-15 补充）

> 状态：已实现（2026-08-15 落地：顾客端 booking 日历上方画廊 + 占位「预约须知」；管理端 projectConfig 上传/替换/删除/排序/说明；后端 updateProject/getProject/getProjectAdmin/deleteProjectFile）；**设计原型已整合进 `second-design.html`**（cBooking 日历上方画廊 + 占位「预约须知」、aConfig「介绍图片」管理卡：上传/替换/删除/排序/说明，≤9 张）。

### 10.1 顾客端展示
- **位置**：每个预约项（project）的**预约页（booking）**，在「项目名」下方、**日历 / 日期网格上方**。
- **形态**：横向画廊（scroll-view / swiper），可点击放大预览（`wx.previewImage`）。
- **初始化占位**：`introImages` 为空时，展示一个**占位块**，文案写「**预约须知**」+ 默认提示（如"请准时到店，如需取消请提前在『我的预约』操作"）。不依赖二进制图片资源，用 CSS 占位即可（满足"占位的图片"语义）。
- **数据**：`project.introImages`（每条含 `fileId` + 解析后的 `url` + `caption` + `sort`），由 `getProject` 在读取时解析临时 URL。

### 10.2 管理端配置（projectConfig，owner-only）
- 「介绍图片」区块：**上传 / 替换 / 删除 / 排序（上移·下移）/ 添加说明文字**。
- 上传：`wx.chooseMedia` → `wx.cloud.uploadFile`（路径 `projects/<projectId>/...`）→ 写 `fileId` 到 `introImages` → `updateProject` 整组替换。
- 删除：先云函数 `deleteProjectFile`（`cloud.deleteFile`）删云存储文件，再 `updateProject` 移除元数据，**避免孤儿文件**。
- 排序 / 说明：重排数组或改 `caption`，`updateProject` 整组保存。

## 13. 公众号专属菜单页（新增 · 2026-08-16 落地）

- 入参 `projectId`（可选）：指定某预约项目的菜单；缺省取**全店已发布项目**的在售菜品。
