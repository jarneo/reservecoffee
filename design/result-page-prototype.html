交互说明

1. 与原弹层的关系

上方成功卡视觉沿用 confirm.wxss 的 .success-*（图标/标题/副标题/信息行/按钮），但从 position:fixed 遮罩改为文档流内块——因此不再需要 z-index 避让，也不会与 page-loading（z=1050）冲突。

2. 相比原弹层补齐的字段

原弹层只有 4 个字段（项目/日期/场次/人数 + 待审核分支），本次新增 1 项：

  • 联系电话：用 this.data.phone（顾客刚自己填的，必有）。

❌ 不做预约号：createReservation 返回的 id 是 32 位 hex 内部主键（截前 8 位对用户也无意义），顾客不会用、店员也不查，纯增噪音。

门店地址本期不做：config_homepage 只有 logo/tag/heroImage/intro 四字段，projects 也无地址字段，做需 4 处改动。

3. 下方菜单：完整菜单 + 分类 tabs

用 <category-tabs> 组件 + 真·瀑布流双列（直接 require('../../utils/masonry')，与首页共用同一实现，不二次造）。

数据取 listCategories + listProducts（2 跳 Promise.all），不调 getHomepage（后者连带返回 projects + 全量 schedules，8+ 次 DB 往返，其中 4 次对结果页无用）。

顶部「门店信息」标题的右侧灰字会显示当前生效的默认分类来源，便于验收时确认配置是否命中（见第 5 节）。

4. 默认分类：项目级配置

分类是全局跨项目集合（_lib/index.js:20-22 注释「全局类目，不按项目隔离」），但不同项目热销分类不同（咖啡 vs 清酒）→ 必须项目级。

层改动
存储projects 新增 resultCategoryId（存分类 _id，空串=全部）
云函数updateProject 白名单加字段；getProject:109 加 1 行下发
配置页projectConfig 三处：data.global 声明 / 读回 / saveAll 提交；wxml 加 picker

getProjectAdmin:89 是 ok({ project, schedules }) 整文档直传，无需改动即自动带上新字段。

5. 分类失效兜底（三层）

  • L1 存储：updateProject 存 _id 字符串，分类被删后成悬空引用（不报错）。
  • L2 主兜底：result.js 读时校验 categories.some(c => c._id === want)，无效回退 'all'。
  • L3 UI：catOptsIdx = Math.max(0, cats.findIndex(...))，findIndex 返 -1 时落到「全部」。

6. ⚠️ 时序陷阱（本方案最易踩的坑）

首页 index.js:121 是这个写法：

if (this.data.activeCat === 'all') { patch.products = top; patch.colA = …; patch.colB = … }

若在 onLoad 就把 activeCat 设成具体分类 id，该分支不执行 → 菜单永久空白，且 boot 图片门不结算（只有数据门）→ 用户看到「空菜单 + 无遮罩」的诡异状态。

✅ 正确模式：onLoad 只存实例变量 this._wantCat（不进 data），等 categories 返回后校验有效性再决定 activeCat。

首页本期不修（?cat= 的唯一来源是结果页返回首页，而已决定不带）→ 会在 index.js:121 加注释指向本页的正确模式，防止未来维护者重蹈。

7. 跳转与兜底

wx.redirectTo（不是 navigateTo：成功后不该回得到表单页）。参数用 encodeURIComponent 逐字段拼，绝不塞 JSON。

必须加 fail 兜底：redirectTo 失败时用户停在表单页且看不到成功反馈 → 会以为提交失败而重复下单。所以保留 confirm.wxml 的 .success-mask WXML/WXSS 作为 fallback 分支：正常走结果页、异常走原弹层。

8. 订阅消息

✅ confirm.js:201-234 的 requestNotify() 完全不动——它在 tap 手势栈内、doSubmit 之前，上下文完整。

结果页不能自动申请订阅（跳转后手势上下文必然丢失），且本次不做「开启到店提醒」按钮（96% 用户提交时已授权过，添个用不上的按钮反而是噪音）。将来若需要，加一个 bindtap 同步调 requestSubscribe(tmplIdsOfPlan(plan, subs)) 即可——必须用 tmplIdsOfPlan 而非 tmplIdsOf，后者返 5 个超微信上限报 20003。

9. 待审核态

needReview 为真时标题改「提交成功，待审核」、副标题改「店家审核通过后将发送预约成功通知」，其余结构不变（与原弹层一致）。

10. 新页面须注册的组件

result.json 注册 category-tabs + path-bar（项目约定：新页面必须加路径条）。page-loading 全局已注册，无需重复。app.json 注册位置非 tabBar（tabBar 只有 index/mine）。
