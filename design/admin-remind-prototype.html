本次改动

  • 改名：页面标题、管理台卡片、app.json 导航名一律「收件箱」→「提醒」。收录范围 = 新预约 · 取消 · 预约审核 · 评论审核（四类）。
  • 顶部新增「预约情况」卡片，位于 tab（全部/未读）之上，是管理员进页面的第一眼。
  • 日期条：横向滚动，取所有项目有场次的日期并集，只显示今天及以后；灰掉的日期 = 该日无任何场次。默认选中今天。
  • 表格：行 = 当日全部项目的时段并集（升序去重），列 = 项目；单元格 已约/容量，无此场次显示「—」。

新增：两类审核提醒（v6.6.108）

  • 预约审核（type:'reviewRes'）：createReservation 在项目开启「需审核」时落这条 —— 不额外补一条，只是把原来的 type='new' 换成新类型（否则同一件事提醒两次）。跳 pages/admin/review/review。
  • 评论审核（type:'reviewDish'）：addReview 机器检测通过、进入人工审核队列后落这条。跳 pages/admin/reviewAdmin/reviewAdmin（默认「待审核」tab）。
  • 待处理（实时）：数字由 getInbox 查 reservations.review='pending' / reviews.reviewStatus='pending' 实时得出，不在条目上回写状态 → 处理完自动归零，且 reviewReservation / reviewAllReservations / setReview / cancelReservation 四个函数全部无需改动（批量审核、顾客自行取消等边角路径天生覆盖）。
  • ⚠️ 微信侧暂无「评价待审核」订阅模板（现有 adminReview 是「门店名称/计划就餐时间/用餐人数」的预约语义，不可复用）→ 本次只做收件箱通道。预约侧则复用已有 adminReview，零改动。

数据来源（已确认）

  • schedules：{ projectId, date, closed, sessions:[{id,start,end,capacity,booked,paused}] }
  • booked = 已预约人数（createReservation 按 partySize 加、cancel 减），capacity = 名额上限
  • 项目数少（3–4 个）→ 做列；时段数随日期变化 → 做行。这样列数稳定、行数自适应
