# 预约小程序 · 设计系统 v5（黑白极简 · 项目制配置）

> UI Designer 交付。本文件为设计令牌、组件规范与信息架构说明，配套可交互原型 `design-system.html`（顶部可切「顾客 / 超级管理员 / 普通管理员」三视角，共用一套组件）。

---

## 1. 设计原则

1. **黑白基调，不用彩色**：所有状态靠「描边样式（实线 / 虚线）+ 字重 + 文字标签」区分，不依赖红绿等彩色，确保极致简洁与跨端一致。
2. **顾客与管理共用一套体系**：管理端不在视觉上另起炉灶，只在顾客界面基础上「额外展示数据与操作」。
3. **以「预约项目」为配置单位**：首页展示的是「预约项目」，每个项目独立配置（图标 / 简介 / 场次 / 全局规则），配置后发布到首页。
4. **可编辑首页**：首页的 logo、头图、文字介绍均可在管理后台修改并实时同步。
5. **授权基于微信 OpenID**：超级管理员 / 普通管理员不是独立账号，而是被授权（绑定）的微信用户。

## 2. 设计令牌（Token）

### 色彩（仅黑白灰，WCAG AA）
| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#FFFFFF` | 页面背景 |
| `--ink` | `#0A0A0A` | 主文字 / 主操作（黑按钮） |
| `--ink-2` | `#6B6B6B` | 次级文字（说明、占位） |
| `--ink-3` | `#9A9A9A` | 弱化文字（脚注、禁用） |
| `--line` | `#E7E7E7` | 描边 / 分隔线 |
| `--fill` | `#F5F5F5` | 浅填充（开关底、徽标底） |
| `--fill-2` | `#FAFAFA` | 图标底 |

对比度：正文 `#0A0A0A` on `#FFFFFF` ≈ 18:1（远超 AA 4.5:1）；次级 `#6B6B6B` on `#FFFFFF` ≈ 5.7:1（满足 AA）。

### 字体
- 字体族：`PingFang SC / Noto Sans SC / system-ui`
- 字号：12 / 13 / 14 / 15 / 16 / 17 / 20 / 22
- 字重：400 常规 / 600 半粗（仅用于标题、强调、主按钮）
- 行高：1.5

### 间距（4 的倍数）
4 / 8 / 10 / 12 / 14 / 16 / 18 / 24

### 圆角
- 小组件（输入框、徽标）：`10px`
- 卡片 / 容器：`14px`
- 胶囊（日期、分段）：`999px`

### 阴影
刻意**不用阴影**，仅用 1px 描边表达层级；hover / active 时把描边变黑（`--ink`）表达选中，避免视觉噪音。

## 4. 信息架构（14 屏，共用组件）

### 顾客视角
1. **首页** — Hero（logo 文字 + 头图 + 文字介绍）+ 预约项目卡片列表（独立图标、简介、脚注）。点卡片进预约。
2. **预约 · 选日期/场次** — 横向日期条 + 2 列大网格场次卡（满/暂停置灰不可点）。
3. **确认预约** — 项目摘要 + 到场人数步进 + 称呼 + 手机号 + 备注 + 订阅消息开关。
4. **我的预约** — 预约记录 + 四种状态徽标（预约成功 / 待审核 / 已取消 / 已过期）；「待审核 / 预约成功」可主动取消（二次确认弹窗）；超过有效期的预约自动判为「已过期」且不可取消。

### 超级管理员视角（owner）
5. **管理台** — 统计（今日预约/待审核/可约场次）+ 首页配置 / 项目管理 / 审核 / 管理员管理 / 查看预约人。
6. **首页配置** — 可改 logo 文字、顶部标签、头图（实时预览）、文字介绍；保存即同步顾客端首页。
7. **项目管理** — 项目列表（图标、需审核/提前天数/每日次数、草稿/已发布），点进配置；可新建。
8. **项目配置（核心）** — 单页完成一个项目的全部设置：
   - **可预约日期**：展开月历，点某日选中；
   - **当日场次**：选中日后下方出现该日场次编辑（开始/结束、人数上限、暂停/恢复、添加场次）；
   - **复制当天设置**：到当月 / 下月 / 下周 / 全部月份；
   - **项目全局设定**：需审核开关、暂停/开放、每日次数上限、提前可预约天数；
   - **发布**：保存草稿 / 发布到首页。
9. **查看预约人** — 按项目→日→场次列出预约人，点进详情卡（姓名/电话/人数/项目/场次/备注/审核），一键「📞 拨打电话」（`wx.makePhoneCall`）。
10. **审核** — 需审核项目的待审列表，通过/拒绝（通过则微信通知用户）。
11. **管理员管理** — 基于微信 OpenID 的授权列表（超级/普通）、权限说明、新增（填 OpenID 或审批申请）、移除。

### 普通管理员视角（manager）
12. **管理台** — 统计 + 仅「项目场次」「查看预约人」入口。
13. **项目场次** — 表格化展示各日期场次（时间段 / 可约名额 / 状态），支持单场次「更改预约名额」（步进设新名额，下限 = 已预约人数）与暂停/恢复；不可改全局配置、无审核/授权/发布。
14. **查看预约人** — 同 9，含联系方式与拨号。

> 普通管理员权限边界：查看预约信息、控制可预约场次（**更改单场名额 / 暂停场次**）。无项目配置、审核、授权、发布权限。注：v6.2 起「更改单场名额」已对普通管理员开放（此前 v5.1 约定普通管理员不可改名额，本次按新需求放开；若需收紧，可在 `changeCapSheet` 按角色隐藏入口）。

## 5. 关键交互

- **首页可编辑**：管理后台「首页配置」改 logo/图/文 → 保存后顾客端首页实时变化（数据来自 `config.homepage` 集合）。
- **项目配置单页化**：日历 + 选中日场次 + 复制 + 全局设定 + 发布，全部在一个页面内，降低跳转复杂度。
- **复制当天设置**：选中某日场次后，一键复制到当月 / 下月 / 下周 / 全部月份，避免重复配置。
- **查看预约人 + 拨号**：管理端点场次→弹层列姓名→点某人出详情卡→「📞 拨打电话」走 `wx.makePhoneCall`，无需后端权限（纯客户端）。
- **微信授权**：用户进入管理端，`cloud.getWXContext().OPENID` 取微信身份，比对 `admins` 集合判定 owner/manager；店主可授权店员为普通管理员。

## 6. 无障碍（WCAG AA）
- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1（满足）。
- 点按目标 ≥ 44px（按钮、场次卡、日历格均满足）。
- 状态不仅靠颜色：用文字标签（剩X/已满/已暂停/待审）+ 描边样式（实线/虚线）双重表达。
- 可聚焦：开关、步进器、按钮均有清晰交互态。

## 9. v6 增补（可约 / 不可约日期治理）
- **新增数据概念 `openDays`**：每个预约项目持有「可预约日期集合」。它是顾客端日期可点选的**唯一权威来源**，与 `sched[day]`（当日场次）解耦——某天可约但场次可为空。
- **顾客端日期控件（可约 vs 不可约）**：
  - 两周静态两行网格中，**可预约日期**为正常描边、可点击选中；**不可预约日期**置灰（`--fill` 背景 + 弱化文字 + `cursor:not-allowed`），**完全不可选中**（无 `onclick`，`pickDay` 内二次拦截）。
  - 日期网格上方加**图例**：● 可预约（可选）/ ● 不可预约（置灰禁用），视觉与交互双重区分。
- **管理端项目配置 · 日历可约治理**：
  - 展开月历中每个日期标注状态：**「可约」**（实线描边 + 加粗）或 **「休」**（浅灰填充、弱化），并标场次数（如「3 场」）。
  - **多选批量**：点选日期进入 `calSel` 选中集（描边高亮 outline）。选中集 = 可约，未选 = 不可约。
  - **批量工具栏**（日历下方）：显示「已选 N 天 · 选中=可约，未选=不可约（顾客端不可选且不展示）」，提供「批量开放选中」「批量关闭预约」「清除」。
  - **单日选中**时下方展示该天场次编辑器（添加/编辑/暂停/人数/描述/复制）；多选时提示批量操作；空选时提示说明。
  - 「添加场次」会自动把当天纳入 `openDays`（添加即视为可约），保证数据一致。
- 设计原则延续：状态靠描边/字重/标签区分，不引入彩色；不可约信息在顾客端直接隐藏而非仅置灰（配置侧「可不展示」语义由 `openDays` 决定）。

## 10. v6.1 增补（取消保护 + 布局优化 + 场次时间展示）
- **关闭/取消日期的预约保护（后端拦截）**：已开放项目若某日期已被顾客预约（`booked>0`），管理员**不可取消/关闭该日可约状态**。`batchClose()` 内置 `dayHasBookings()` 守卫——命中即 toast「该日期已有人预约，无法取消当日预约：<日期>」，并仅关闭无预约的选中日；其余选中日照常生效。对应云函数 `setOpenDays` 写前同样拦截。
- **「清除选择」按钮位置优化**：原置于批量工具栏标题行右上角、易误触且与数据操作混排。改为：标题行仅保留说明文案；「批量开放选中 / 批量关闭预约」置于操作区且**未选中任何日期时禁用**；「清除选择」独立成行于操作区下方（仅在有选中时出现），与数据写操作在视觉上分离，降低误触。
- **场次时间设定展示与配置（补全）**：单日场次卡片显式标注「场次时间 开始 – 结束」+ 状态标签（可预约/已暂停）+ 人数上限/已约；「添加/编辑场次」底部弹层表单含开始时间、结束时间（time 输入）、人数上限、场次描述，完整覆盖各场次的起止时间设置与展示。

## 11. v6.2 增补（项目场次页 + 我的预约四态）

### 11.1 管理员「项目场次」页（owner & manager 共用）
- 顶部项目切换标签（多项目时切换）；汇总块：日期数 / 开放场次 / 剩余名额。
- 按日期分组的**表格**：列 = 时间段 / 可约名额（剩X/总 · 已满 · 暂停显示「—」）/ 状态（可预约·黑边、已满·灰底、已暂停·虚线）/ 操作。
- 操作：每场次「改名额」「暂停/恢复」。满场与已暂停场次也可调高名额以备后用（示例：8月14日 14:00–15:30 名额 6→8，已约6，保存后还可预约 2 人）。

### 11.2 更改预约名额（单场次）
- 点「改名额」→ 底部弹层：展示 项目 / 日期 / 场次 / 已预约人数；步进器设「新名额」，**下限 = 已预约人数**（降低不移除已约顾客）；实时显示「调整后还可预约 N 人」。
- 保存即更新该场次 `cap`，**仅对所选日期该场次生效**：`saveCap()` 只写 `sched[day][sid].cap`，不影响其他日期/场次。
- 弹层明确文案：「该调整仅对 <日期> <时段> 这一场次生效，不影响其他日期或其他场次。」

### 11.3 顾客端「我的预约」四态
- 状态：待审核（虚线）、预约成功（黑边）、已取消（灰底）、已过期（虚线 + 弱化）。状态靠描边 / 字重 / 文字标签区分，不引入彩色。
- 取消：仅「待审核 / 预约成功」出现「取消预约」按钮；点击弹**二次确认弹窗**（确认取消 / 再想想），确认后状态 → 已取消并释放该场次名额（`releaseSlot` 将对应 `booked -1`）。
- 自动过期：`effStatus()` 以原型基准时间 `NOW_DEMO` 比对预约结束时间，超过有效期的 ok / pending 自动显示为「已过期」，且不再提供取消按钮（过期卡片整体弱化 `.card.dim`）。

### 11.4 权限模型（项目场次页）
- owner 与 manager 均可见该页并改名额 / 暂停；区别在全局层——manager 无项目配置、审核、授权、发布入口（见管理台菜单）。
- 若需收紧普通管理员改名额权限，在 `changeCapSheet` 按角色隐藏入口即可（数据层 `cap` 仍是单场次字段）。

### 11.5 后端映射（CloudBase · 微信小程序 + 云开发）
- **数据**：`projects.sched[date][session].cap / booked / paused`。名额为单场次字段，`cap` 变更天然只影响该场次。
- **云函数 `updateSessionCap(sessionId, newCap)`**：事务内校验 `newCap >= booked` 后单文档更新 `cap`；写前拦截（避免名额低于已约）。
- **顾客取消 `cancelBooking(bookingId)`**：校验状态 ∈ {pending, ok} 且未过期，事务内 `booked - 1` 并置 `status = cancelled`；过期由读取时计算（结束时间 < now 且状态非 cancelled → expired），无需写库。
