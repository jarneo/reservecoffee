管理员通知「按项目分配」改造 · 交互原型（含新增项目处理）

当前所有 owner/manager 都会收到全部项目的通知。本次改造在管理员配置页内新增「按项目分配」能力：指定「哪些管理员接收哪些项目」的新预约 / 取消 / 待审核通知。关键边界——新增项目默认通知全体管理员（与现状一致、零丢单），店主随后可收窄。下方原型展示结构差异、可交互矩阵、分配逻辑、新增项目处理与前后页面差异。

品牌色 #7A5230 接收通知 不接收 全部项目（默认）

1现状结构（全部管理员 ↔ 全部项目）

触发：createReservation / cancelReservation / 审核通过 / setReview
↓
notifyAdmins(db, { templateId, data, page })
遍历 admins 中 role ∈ [owner, manager] 的全部人，逐个 sendSubscribe
↓
收件人 = 全部 3 owner + 5 manager（共 8 人）
pushInbox 兜底同样面向全部人
⚠️ 函数签名无 projectId，无法区分项目；任何项目有新预约，8 人全收。

2改造后结构（项目维度可配）

触发：同上，已携带 projectId，并读取 project.notifyAdmins
↓
notifyAdmins(db, { projectId, templateId, data, page })
若项目 notifyAdmins==='all' → 全部；否则只发在名单内的 owner/manager
↓
收件人 = 该项目 notifyAdmins 指定的人
✅ 新项目 notifyAdmins 默认 'all' → 自动全员通知，零丢单；店主随后收窄。

数据模型变更（projects 集合文档）

// 在 projects 文档新增字段（缺失 = 'all'，兼容旧数据 / 新项目）
{
  _id: 'p1', name: '法兰绒深烘咖啡', ...,
  notifyAdmins: 'all' | ['openid1','openid3']   // ★ 新增：谁收本项目通知
}
// 管理员文档无需改动（角色门控 + 订阅额度仍在 admins 文档）
// admins: { openid, role, nickname, note, subscriptions:{adminNew,adminCancel,adminReview} }
采用项目维度存储而非管理员维度：新增项目天然默认全员（安全），避免「白名单模型下新项目漏通知被收窄管理员」的坑；管理员维度的「通知范围」编辑视图由前端跨项目计算得出，写入各 project 文档。

2通知分配矩阵（可交互 · 列=项目，行=管理员）

在 管理员管理页（admins） 每位管理员卡片上加「通知范围」→ 弹出此矩阵；同样可在 projectConfig（每项目「通知管理员」） 编辑，二者写回同一个 projects.notifyAdmins。点格子试改，右侧模拟器实时显示某项目事件会通知到谁。

⚠️ 列头自带「全部 / 指定」开关：切到「指定」后逐管理员勾选；新增项目默认「全部」→ 整列默认全勾（见 ④）。

实时模拟：某项目发生事件 → 谁会收到通知

说明：旧逻辑下，无论哪个项目、何种事件，通知都发给全部 8 名管理员；新逻辑下按该项目 notifyAdmins 过滤。

3通知分配逻辑（后端 notifyAdmins 改造）

1
触发函数已携带 projectId，并读取该项目文档的 notifyAdmins 字段。
2
listAdminsFull(db) 取出全部 owner+manager（角色门控不变）。
3
若 notifyAdmins==='all' → 全部发送；否则只保留 openid ∈ notifyAdmins 的管理员进入后续发送。
4
pushInbox 兜底同步按同一名单过滤，保证「不丢单」留痕也只对该项目范围内管理员可见。
5
字段缺失 / 非法 → 按 'all' 处理，历史项目与新增项目均零改动全收（向后兼容 + 新项目安全）。
// _lib/index.js  notifyAdmins 改动（伪代码）
async function notifyAdmins(db, { projectId, templateId, data, page }) {
  const proj = await db.collection('projects').doc(projectId).get()
  const na = (proj.data && proj.data.notifyAdmins) || 'all'  // 缺失=all（含新项目）
  const allowed = na === 'all' ? null : new Set(na)

  const admins = await listAdminsFull(db)          // role ∈ owner/manager
  for (const a of admins) {
    // ★ 按项目名单过滤
    if (allowed && !allowed.has(a.openid)) {
      results.push({ skipped: true, reason: 'not-in-scope', openid: a.openid })
      continue
    }
    // 既有逻辑：订阅额度校验 + sendSubscribe（不变）
    if (subKey && !adminSubbedOf(a.subscriptions, subKey)) continue
    const r = await sendSubscribe({ openid: a.openid, templateId, data, page })
    if (r.errCode === 43101) await markAdminSubInvalid(db, a._id, subKey)
    results.push(r)
  }
  return results
}
权限：配置入口保持 owner 专属（与 notifyConfig / admins 页一致）。manager 仍正常接收其被授权的项目通知，但不能改分配规则。

4新增项目怎么办？——默认全员，随后收窄

1
创建项目（createProject / publishProject）时，新文档 notifyAdmins 字段默认写为 'all'。
2
因此新项目一旦有人预约，全体 owner+manager 都会收到通知——与现状完全一致，不会丢单。
3
店主随后在矩阵里把该项目从「全部」切到「指定」，剔除不需要的管理员；被剔除者从此不再收到该项目通知。
4
对比「管理员白名单」模型：那种模型下新项目不在任何人白名单 → 被收窄的管理员收不到，需手工补；「项目维度 + 默认 all」天然规避此坑。
点击上方按钮，将在矩阵末尾追加一列「新项目·甜品品鉴」，其「全部/指定」默认 全部 → 整列全勾、全体管理员都会收到它的通知；你再把它切到「指定」即可收窄。
