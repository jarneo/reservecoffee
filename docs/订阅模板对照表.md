## 三、微信优先降级开关（`config.smsnotify.skipSmsIfWxOk`）

**语义**：同一业务事件的微信订阅消息**已送达**（`errcode 0`，即 `sendSubscribe` 返回 `ok:true`）→ 该事件不再补发短信；微信未送达（`43101` 未授权 / `47003` 字段非法 / `-501001` 凭证异常 / 模板未配）→ 短信照发兜底。

- **开启**（`true`）：微信优先，省短信费，避免重复打扰。
- **关闭**（`false`，默认）：不做判断，两条通道都发。

判定实现：`_lib.shouldSkipSms(smsSw, wxRes)`；`ok:true` 的语义见 §六。

落地位置：

| 事件 | 判定时机 | 备注 |
|---|---|---|
| 预约成功（即时短信） | `createReservation` / `reviewReservation` 内，先发订阅再判短信 | 订阅结果落库 `reservations.wxSuccessOk` |
| 预约成功（延迟短信） | `remindReservation` 延迟补发时读 `wxSuccessOk` | 因为此时不再重发微信 |
| 临近 / 结束提醒 | `remindReservation` 循环内用当次订阅结果判断 | — |
| 前一天通知 | `remindReservation` 内用当次订阅结果判断 | — |
| 取消通知 | `cancelReservation` 内用 `reserveCancel` 订阅结果判断 | 判断通过则**不写** `smsCancelAt` |

## 五、通知时间点汇总（按业务流）

| 顺序 | 业务动作 | 时间点 | 谁收到 | 用哪个模板 |
|---|---|---|---|---|
| 1 | 顾客提交预约（免审） | 立即 | 顾客 + 管理员 | reserveSuccess + adminNew |
| 2 | 顾客提交预约（待审） | 立即 | 仅管理员 | adminReview |
| 3 | 管理员审核通过 / 拒绝 | 立即 | 顾客（仅通过时 reserveSuccess）+ 管理员（adminReview） | reserveSuccess + adminReview |
| 4 | 顾客 / 管理员取消 | 立即（订阅）；短信延迟 3 分钟 | 顾客（reserveCancel）+ 管理员（adminCancel）；短信仅顾客 | reserveCancel + adminCancel + 短信 cancel |
| 5 | **提前一天通知（新增）** | **每天 17:30（可配）** | 仅顾客 | **dayBefore + 短信 2729722** |
| 6 | 开场前提醒 | 开场前 ≤60 分钟（定时每 15 分钟扫） | 仅顾客 | reminder + 短信 approaching |
| 7 | 结束提醒 | 场次结束（定时每 15 分钟扫） | 仅顾客 | reminderEnd + 短信 expired |

**提前一天通知的规则细节**：
- 目标：`date == 次日` 且 `status == 'confirmed'` 的预约；每天固定时刻后首次扫描时发送（即 17:30 起的第一轮定时）。
- **同一顾客次日多笔预约，只发最早一场**（按 `sessionStart` 升序，其次 `createdAt`）；其余打 `dayBeforeSkipped='dup-openid'`。
- 幂等：每笔打 `dayBeforeNotified: true`，结果落库 `dayBeforeNotify`（微信）/ `dayBeforeSms`（短信）。
- 过了当天就不再补发（`date` 变为「今天」后自然不再匹配）。

## 六、运行期语义与排查（必读）

**`sendSubscribe` 返回值的真实含义**：`errcode 0` = 微信服务端**受理并投递**（消耗 1 次订阅额度、进用户「服务通知」），代码记为 `ok:true`；**没有**「用户已读/已看到」的回执。常见错误码：

| errCode | 含义 | 处置 |
|---|---|---|
| `43101` | 用户无可用的订阅次数（未授权 / 已用完 / 曾拒绝且勾选「总是保持」） | 用户重新授权（清授权缓存：长按小程序 → 移除，再进小程序重新提交） |
| `47003` | data 字段键不匹配或 `thing` 值 > 20 字 | 按本文档核对键名与字数 |
| `-501001` | 云调用网关拿不到有效微信 token | 属**上下文/凭证**问题，见下 |
| `-604101` | 函数未声明 `permissions.openapi` | 用微信开发者工具「上传并部署」而非 MCP |

**定时调度判据**：`remindReservation` 的定时器必须用**微信开发者工具「上传触发器」**注册（CLS 日志里 `request_source=TCB_API`），这样才能拿到微信 token；用 MCP/SCF 建的原生定时器（`request_source=TRIGGER_TIMER`）必然 `-501001` / `-501007`。

**`-501001` 的判别价值（2026-09-11 更新）**：`-501001` 只在**特定调用上下文**下出现——CLI / MCP `invokeFunction` / 控制台「云端测试」调用必然是假阴性，无判定价值。**真机判据看定时轮次的落库结果**。2026-09-11 23:30 的 `TCB_API` 轮次返回 `43101`（而非 `-501001`），**证明云调用凭证当前有效**（网关拿到 token 且被微信受理）；同日早前的 `reminderNotify` 仍是 `-501001`，说明凭证阻塞是在当日解除的，**改动过凭证/关联后应尽快用一次真实定时轮次复测**。

**排查顺序**：① 函数代码是否为最新（CodeInfo ModTime）；② `reservations.*Notify.*` 落库结果（含 errCode）——这是**权威判据**；③ 前端 TPL 与云端 `TPL` 是否一致；④ 让用户重新授权后复测；⑤ 核对微信后台模板关键词。

## 七、哪些地方可以调整

**✅ 可改（改代码局部 / 管理台配置即可）**
1. **固定文案**：各 `thing*` 的提醒语是硬编码，改字面量即可（`thing` 上限 20 字，改完务必数一遍）。
2. **店铺名**：`config.store.name`，改后订阅/短信口径同步变。
3. **发送时刻与提前量**：管理台「通知配置」可改——临近前/后与偏移、过期前/后与偏移、成功短信延迟、前一天通知时刻（默认 17:30）、取消短信延迟（默认 3 分钟）；另有「微信优先降级」总开关。
4. **短信模板 ID**：管理台「通知配置 → 短信通知配置」填 5 个模板 ID。
5. **触发事件增减**：如「审核通过也通知管理员」，加一段 `notifyAdmins`。

**❌ 不可随意改**
- **微信键名**（thing10/time12/phone_number2/const4 等）：由后台模板结构决定，改键名即 `47003`。
- **一次性授权机制**：订阅消息一次授权消耗一次，需用户再次点击授权（微信限制）。
- **短信正文**：无参数模板，正文只在腾讯云控制台维护，代码改不了。
