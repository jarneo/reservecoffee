## 三、双层开关逻辑（与订阅消息一致）

- **项目总开关**：`projectConfig` 里的「开启服务号通知」（`projects.mpNotify`，默认开）。
- **全局单模板开关**：`config.mp` 各键（`adminNew` / `reserveSuccess` / `reserveCancel` / `adminReview`，默认开）。
- **判定**：`项目总开关 ON && 单模板开关 ON` 才发送；任一关都不发。两者不冲突。
- 短信配置不在此层级，仍走原 `smsEnabled` 逻辑。

## 四、关于 AppSecret（重要澄清）

**本实现不需要在代码里写服务号 AppSecret。**  
服务号模板消息通过云开发 `cloud.openapi.templateMessage.send` 发送，凭据由「云环境绑定服务号」后自动托管（与订阅消息同理）。采集 `mpOpenid` 也仅靠云开发可信上下文 `FROM_UNIONID`，无需调 `user/info`、无需 AppSecret、无需出网。  
→ 历史对话里也没有留存服务号 AppSecret 明文（之前只提供过小程序 `WX_APP_SECRET`，已走环境变量，与服务号无关）。

## 六、微信 time 字段格式注意（易踩坑）

`time3` / `time7` 是**时间类型**字段，微信只接受标准格式（`YYYY-MM-DD HH:MM` 或 `HH:MM`）。代码里填的是**开始时刻**（如 `2026-08-22 14:00`），未含结束时段。

- 若你的模板里该字段实际是 `thing` 类型（文本），可自由写「8月22日 14:00-15:00」；
- 若确为 `time` 类型，发送时含「-15:00」会被拒（`40003` 类）。建议保持只填开始时刻，或在公众平台把模板该字段改为 `thing` 类型。
- `const1` 是固定值字段，发送值须与模板申请时填的常数**完全一致**（代码用「已预约」/「已取消」）。
