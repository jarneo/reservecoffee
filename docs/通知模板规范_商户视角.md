# 预约通知模板规范（商户视角 · 双角色分流 + 留座语气）

> 适用：微信原生小程序「咖啡店预约」+ CloudBase。本文从**商户/店主**视角，整理两套发送模板：
> ① 微信订阅消息（实时推送，分两条线：预订人 A 线 / 管理员 B 线）② 短信（腾讯云 SMS，仅预订人，单条 ≤70 字）。
> 目的：去微信/腾讯云后台申请模板时，直接照此填写字段，避免来回试错。

---

## 〇、店铺名（以店铺名义发消息）

所有「以店铺名义」的文案统一使用店铺名 **二曜路8号咖啡和清酒**。该名称是**可直接获取的配置**，不再硬编码在多处：

- 云函数读 `config` 集合文档 `_id:'store'` 的 `name` 字段；未配置时回退常量 `二曜路8号咖啡和清酒`（`_lib/index.js` 的 `DEFAULT_STORE_NAME` / `getStoreName`）。
- 短信的店铺名来自腾讯云 SMS 控制台的**签名 SignName**（配置在 `config_sms` 或环境变量 `SMS_SIGN_NAME`），模板正文不含签名前缀。
- 改店名 = 改 `config.store.name`（或 SMS 签名），无需动代码。

## 一、通知总览（双角色）

| 触发时机 | 接收人（订阅消息 A 线·预订人） | 接收人（订阅消息 B 线·管理员） | 接收人（短信） | 说明 |
|---|---|---|---|---|
| 顾客提交预约（免审核） | 预订人 `预约成功` | 管理员 `新预约提醒` | 预订人（项目开 `smsEnabled`） | 管理员含 owner + manager |
| 顾客提交预约（需审核） | 预订人 `待审核` | 管理员 `新预约提醒` | 预订人（同上） | 同上 |
| 店主审核通过 | 预订人 `审核结果` | — | 预订人（同上） | — |
| 顾客取消预约 | 预订人 `预约取消` | 管理员 `预约取消提醒` | 不发 | 短信仅成功/待审核场景 |

- **管理员 = `admins` 集合中 `role` 为 `owner` 或 `manager` 的全部人**（代码 `listAdminOpenids` 查 `role in ['owner','manager']`）。owner 与 manager 都收 B 线通知。
- 订阅消息需接收方**本人在小程序里点过"允许"**才送达；短信无需授权，但需配密钥 + 项目开 `smsEnabled`。
- 所有模板 ID 当前为占位 `TPL_ID_*`，未配置时发送自动跳过、不报错（"接线未通电"）。申请到真实 ID 后，回填到 `cloudfunctions/_lib/index.js` 的 `TPL` 常量即可全量生效（会经部署同步到各函数 `lib.js`）。

## 二、微信订阅消息（分两条线，共 6 个）

### A 线 · 给预订人（亲切 · 以店铺名义）

**1. 预约成功通知（顾客）**
- 触发：免审核项目预约提交成功
- 关键词：`thing1` 店铺名（`getStoreName`）· `thing2` 日期场次（如 8月20日 14:00-15:00）· `thing3` 几人位（如 2人位）· `thing4` 温馨提示
- 示例：**"二曜路8号咖啡和清酒：您预约的 8月20日 14:00-15:00，2人位，已为您留座，请准时赴约，期待与您相见～"**

**2. 待审核通知（顾客）**
- 关键词：`thing1` 店铺名 · `thing2` 日期场次 · `phrase3` 状态（待审核）· `thing4` 温馨提示
- 示例：**"二曜路8号咖啡和清酒：您的 8月20日 14:00-15:00 预约已收到，正在为您安排，结果将第一时间通知～"**

**3. 审核结果通知（顾客）**
- 关键词：`thing1` 店铺名 · `phrase2` 结果（已通过/未通过）· `thing3` 日期场次 · `thing4` 温馨提示
- 示例（通过）：**"二曜路8号咖啡和清酒：您的预约已通过，8月20日 14:00-15:00，已为您留座，请准时光临～"**

**4. 预约取消通知（顾客）**
- 关键词：`thing1` 店铺名 · `thing2` 日期场次 · `thing3` 温馨提示
- 示例：**"二曜路8号咖啡和清酒：您 8月20日 14:00-15:00 的预约已取消，期待下次为您留座～"**

### B 线 · 给管理员（owner + manager，含联系方式）

**5. 新预约提醒（管理员）** ← 含「联系方式」字段 `character_string4`
- 触发：任意顾客提交预约（含待审核）
- 关键词：`thing1` 预约项目 · `thing2` 预订人 · `thing3` 日期场次 · `character_string4` 联系方式（手机号）· `thing5` 几人
- 示例：**"【新预约】法兰绒深烘咖啡 · 张三 · 8月20日 14:00-15:00 · 13800001111 · 2人"**
- 代码字段（`createReservation`）：`thing1=项目名, thing2=称呼, thing3=友好日期时段, character_string4=phone, thing5=人数`

**6. 预约取消提醒（管理员）**
- 触发：顾客取消预约
- 关键词：`thing1` 预约项目 · `thing2` 预订人 · `thing3` 原日期场次 · `character_string4` 联系方式 · `thing5` 几人
- 示例：**"【取消】法兰绒深烘咖啡 · 张三 · 8月20日 14:00-15:00 · 13800001111 · 2人"**

> 授权引导：owner **与 manager** 进 `hub` 都弹 5/6 授权（`hub.js` 的 `enableAdminNotify`）；预订人在 `confirm` 提交时授权 1~4（`reserveSuccess/reserveReview/reviewResult/reserveCancel`），在 `mine` 取消时授权 4。模版 ID 配好后即生效，无需改前端。

## 三、短信模板（仅预订人 · 单条 ≤70 字）

> 计费：国内短信 **70 汉字/条**，超出拆多条另计。下单条、亲切、含留座。
> 店铺名由腾讯云 SMS **签名 SignName**（= 二曜路8号咖啡和清酒）提供，模板正文不含签名前缀。

### A. 顾客-预约留座（成功/待审核通用，单条）
- 模板正文（注册到腾讯云，**不含签名**）：
  `亲爱的{1}，已为您留座：{2} {3}，{4}。到店报手机号即可，期待相见～`
- 变量：`{1}`称呼 `{2}`日期(友好，如 8月20日) `{3}`场次(如 14:00-15:00) `{4}`几人位(如 2人位)
- 示例（实测含签名约 57 字，单条）：
  `【二曜路8号咖啡和清酒】亲爱的张三，已为您留座：8月20日 14:00-15:00，2人位。到店报手机号即可，期待相见～`
- 待审核场景复用同一模板（"已为您留座"语义对免审/待审均成立）；如确需区分可在申请时单开模板，当前代码用单模板即可。
- 代码：`cloudfunctions/_lib/sms.js` 的 `sendReservationSms`，`TemplateParamSet=[称呼,日期,场次,几人位]`，`status/notice` 分支已删除。

> 说明：短信**只发预订人**，不再给管理员发短信（管理员走 B 线订阅消息）。原文档 B/C 管理员短信模板已作废。

## 四、配置清单（拿到真实模板 ID 后回填）

1. **微信订阅消息（6 个）** → 微信公众平台「订阅消息 → 我的模板」申请，拿到模板 ID，回填：
   - `cloudfunctions/_lib/index.js` 的 `TPL` 常量：`reserveSuccess / reserveReview / reserveCancel / reviewResult`（A 线 1~4）、`adminNew / adminCancel`（B 线 5~6）。
   - 字段类型务必与后台申请一致（尤其 B 线的 `character_string4` 是字符型，不是 thing）。
2. **店铺名配置**：向 `config` 集合写文档 `_id:'store', { name: '二曜路8号咖啡和清酒' }`（不写则用代码默认常量）。
3. **短信（A）** → 腾讯云 SMS 控制台申请签名（= 二曜路8号咖啡和清酒）+ 上述单条模板，拿到 `SignName / TemplateId / SmsSdkAppId`，填入：
   - `config_sms` 文档（`_id:'sms'`）的 `signName / templateId / smsSdkAppId / secretId / secretKey`，或环境变量 `SMS_SIGN_NAME / SMS_TEMPLATE_ID / SMS_SDK_APP_ID / SMS_SECRET_ID / SMS_SECRET_KEY`。
4. **前端授权已接线**：店主/经理进管理端、顾客提交/取消时弹窗授权，模板 ID 配好后即生效，无需改前端。

> 字段类型提醒：微信订阅消息每个模板有固定关键词结构，类型（thing / phrase / character_string / date / time）须与后台申请完全一致，否则发送失败。B 线 5/6 的「联系方式」是 `character_string4`（字符型），不是 `thing4`。
